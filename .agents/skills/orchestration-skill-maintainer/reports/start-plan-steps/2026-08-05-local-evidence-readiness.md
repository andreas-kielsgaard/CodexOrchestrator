# Local evidence readiness

## Observation

Some Plan Steps required TypeScript or runtime consumer evidence but launched into routes where the dependencies were absent and establishing isolated validation state was not authorized. Workers correctly retained the gate as unproven, but decisive feedback arrived only after later authority was supplied.

## Reader and cause

The launch operation rechecks route, authority, and gates and constructs the self-contained assignment. Earlier wording did not require it to join those facts into one question: whether the Step could execute its required local evidence under the authority actually supplied.

## Revision

Before launch, confirm internally that required local evidence can run within the supplied route and authority. Include an isolated validation boundary only when that authority is needed; otherwise omit routine readiness confirmation from the handoff or keep the Step gated when authority is missing.

## Evaluation

This should prevent implementation from accumulating behind a known unexecutable local gate without prescribing commands, authorizing dependency changes implicitly, or adding launch narration. It keeps environment preparation with the planner and launcher that can control the route rather than creating a separate validation role.
