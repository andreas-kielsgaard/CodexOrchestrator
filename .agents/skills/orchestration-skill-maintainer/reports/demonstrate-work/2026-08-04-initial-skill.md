# Demonstrate Work

## Observation and theory

Ongoing development produces accepted commits, partial implementation, tests, projections, and mockable UI states without a shared method for showing the user what the accumulated work actually enables. A generic review skill starts from a prepared review surface, while implementation agents optimize for completion rather than a coherent demonstration.

## Revision concept

Create a general Codex skill that verifies the capability boundary, classifies productive and simulated evidence, designs one outcome-oriented flow, prepares isolated demo state and minimal labelled fixtures, rehearses it, and hands off an exact demonstration.

## Evaluation

The skill should make partially productive work visible without turning mock data into false end-to-end proof. It permits project-specific demo design while preserving a strong evidence boundary. Product repair and guided evaluation remain separate responsibilities.

## Placement

The skill lives in the general Codex catalogue because it demonstrates work across projects and is not supplied by the product Harness.
