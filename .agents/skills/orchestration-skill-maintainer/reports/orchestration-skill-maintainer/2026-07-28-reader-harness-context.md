# Reader Context and Agent-Controlled Duties

Status: revised. Product code and harnesses unchanged.

## Observations

Earlier maintenance established automatic response to agreed behavior failures, reader-context analysis, affirmative wording, open-ended illustrative lists, and sub-instructions for narrower reusable context.

The worker correction then used phrases such as “remain available” and “passively addressable.” Session addressability is controlled by the parent harness; the worker cannot perform it. Treating it as a role duty encouraged the worker to invent active waiting work.

## Theory

The maintainer required an understanding of harness guarantees but did not explicitly separate those environmental facts from actions the consuming agent can perform. That allowed a relevant parent-harness concern to become meaningless reader-facing instruction.

## Revision

The maintainer's reader-context checklist no longer treats availability as a role-relevant guarantee. Its generic authoring boundary now assigns only actions the consuming session can perform and uses harness-owned facts solely as context for those actions.

Narrow lifecycle sequencing remains in the focused shared concepts and role skills. Their wording now states observable actions: send the notification, end the turn, and handle a later message if one arrives.

## Evaluation

The revision should prevent harness responsibilities from leaking into agent instructions while preserving the context needed to design correct message routes and turn boundaries. It is role-independent and therefore belongs in the main maintainer procedure.
