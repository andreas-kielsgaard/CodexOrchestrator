# Agent-interface-first review preparation

## Observation

The Review Coach repeatedly used generic desktop control for routine launcher discovery, activation, inspection, recovery, and navigation while preparing review surfaces.

## Theory

Environment ownership authorized setup and navigation without making quiet semantic operation the normal route. The first revision loaded the shared skill only when Computer Use was already under consideration and described a safe fallback too prominently.

## Revision

Reformulated the environment guidance to load `$agent-interface-first` whenever review preparation could involve visible UI control. The coach prepares and inspects state through quiet structured routes, treats desktop interaction as a rare exception, routes missing interfaces separately, and prefers another ready review area before a proportionate bounded fallback. Those mechanics stay out of the user response unless they change the current action or evidence.

## Evaluation

The loading boundary appears before tool selection while the detailed principle remains centralized. It should make review preparation less intrusive without blocking a review when a carefully bounded exception is genuinely warranted.
