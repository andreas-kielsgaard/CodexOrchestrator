# Clue-first Plan Step specification

## Observation and theory

`maintain-slice-plan` required detailed Plan Step specifications but did not distinguish precise outcome boundaries from prescriptive solution rules. A planner could therefore satisfy detail requirements by exporting its implementation hypothesis to the worker.

## Revision

Plan Step objectives, deliverables, acceptance, and genuine hard boundaries remain precise. Context, risk, validation placement, and planning hypotheses become a few broad clues, leaving the solution path open. Prescriptive wording is reserved for actual hard boundaries.

## Evaluation

This retains the historical planning depth the user wants while keeping that reasoning in the Slice Plan. Workers receive enough context to orient themselves without being constrained to the parent's provisional method.

The clue boundary now explicitly excludes unaccepted solution candidates and command or check suggestions. Useful context becomes neutral concerns, evidence, or surfaces to inspect.
