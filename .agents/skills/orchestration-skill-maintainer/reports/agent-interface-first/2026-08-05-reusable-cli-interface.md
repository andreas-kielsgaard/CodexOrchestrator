# Reusable CLI interface

## Observation and theory

CLH-01 first interpreted CLI tooling as a one-run coordinate driver. Later, CLS-01 explicitly loaded `agent-interface-first`, found no typed seam for a repeatable retained live flow, and used Computer Use instead of adding bounded task-support tooling.

The skill made tooling conditional on whether the assignment authorized "the capability." A worker briefed to perform product operations could read that as authority to operate the UI but not authority to build a development interface for the same operations. Its temporary-route wording then made desktop fallback an easy compensation.

## Revision and evaluation

Authority for an operation against software under development now includes bounded task-support tooling unless a hard boundary explicitly excludes tooling changes. Retained, repeated, multi-stage, or later-reusable operations are direct clues to build a background-capable CLI or equivalent interface. Desktop control requires identifying both the missing semantic interface and why it cannot be added within the assignment.

The Plan Step role and execution operation now carry the same boundary. This should prevent agents from satisfying the trigger mechanically by loading the skill and then treating the absence of an existing seam as fallback permission. It preserves proportional exceptions and keeps task-support tooling distinct from product-feature scope.
