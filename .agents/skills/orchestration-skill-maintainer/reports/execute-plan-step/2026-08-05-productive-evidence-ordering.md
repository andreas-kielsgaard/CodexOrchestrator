# Productive evidence ordering

## Observation

Repeatedly corrected work often established in-process or synthetic behavior before proving productive persistence, fresh-open recovery, or a real downstream consumer. DWE produced no-change fixture diagnoses before constructing a canonical fresh-open path, while SRH and graph projection defects surfaced only when TypeScript or runtime consumers finally executed.

## Reader and cause

The Plan Step performs the fixed work and chooses its validation method. Existing guidance selected proportionate evidence but did not tell the reader to use early results as implementation feedback or make durable lifecycle and producer-consumer claims executable soon enough to shape the remaining work. Narrow checks could therefore create premature confidence.

## Revision

Use the earliest relevant executable check to guide dependent implementation. For durable, reopen, or recovery outcomes, establish representative state through productive persistence or materialization and exercise fresh-open behavior early. For contract-spanning work, exercise a real consumer once runnable. Synthetic fixtures and source-shape checks remain useful supporting evidence rather than sole authority for productive behavior.

## Evaluation

This should move decisive evidence earlier without selecting commands or banning test helpers. It applies only when the Step's own acceptance includes productive lifecycle or consumer behavior and does not add a later integration gate to local work.
