# Evaluate Plan Step

Judge the returned outcome against the step's effective specification and the Slice Plan.

Inspect the cited artifacts and evidence far enough to decide whether to:

- accept the outcome;
- continue the same Plan Step from a partial result;
- send a precise correction to the same Plan Step conversation;
- request a reserved decision;
- define additional work; or
- revise unstarted projections, dependencies, gates, or sequencing.

For a partial return, first identify the action it enables in this Slice and whether locally actionable candidate work was bundled with it. Resolve the Slice-owned action without treating an immature candidate as review-ready; return the same Plan Step to finish its local boundary before independent evaluation. When the same Plan Step can continue without new authority and no Slice decision, correction, or replanning is needed, send one short continuation without treating the checkpoint as a planning revision or re-ingesting unchanged proof.

Keep the started step's boundary stable unless an authorized correction changes its effective specification. A Plan Step may perform implementation, exploration, review, integration, verification, documentation, or similar work; these work modes do not create additional workflow roles.

Perform ordinary review in this conversation by inspecting the returned artifacts and evidence, deciding their sufficiency, and routing precise corrections to the same Plan Step.

Use returned validation evidence for its exact committed checkpoint. Add validation only when evaluation exposes an uncovered acceptance risk, the evaluated material has changed, or independent reproduction is itself required. Identify the distinct evidence the added work contributes rather than repeating a command as a routine acceptance ceremony.

When returning work to the same Plan Step, state the required outcome and preserve complete, partial, blocked, and clarification as evaluable return dispositions. Carry only the task-local delta, such as the retained checkpoint, newly failed criterion or evidence, required outcome, and changed authority or boundary. Rely on the task's retained assignment and role skill for unchanged proof and mechanics. Use a partial return when the retained result gives this Slice an actionable decision, correction, or replanning boundary; locally actionable continuation remains inside the Plan Step activation.

Create another review or verification Plan Step only when Slice acceptance explicitly requires independent evidence or this evaluation exposes a distinct unresolved concern. State what evidence that step must add beyond rechecking the implementer's return.

For a changed repository outcome, verify that the returned commit contains only attributable Plan Step changes and that unrelated state remains preserved. Do not accept changed work that remains uncommitted. A bounded correction returns as its own commit. A commit records the candidate; this evaluation determines acceptance.

Retain one compact profile-calibration judgment with the disposition: whether the Step completed successfully, whether its selected model or reasoning plausibly affected the result, and the stronger cause when it did not. Task scope, briefing, ownership, environment, evidence seams, build or test duration, and interruption are non-exhaustive alternative causes. Treat successful first-pass work as evidence too; duration or correction count alone does not prove a profile mismatch. Revise future unstarted profiles only when repeated evidence points in the same direction.

State the disposition and the resulting changes to the planning revision, launch register, dependencies, gates, or remaining work. Continue immediately with the correction, plan maintenance, newly ready packet, or combined Slice judgment that the disposition makes actionable.
