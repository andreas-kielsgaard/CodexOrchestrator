# Start Plan Steps

Instantiate the ready work described by the current Slice Plan.

## Recheck readiness

Require a planning revision already presented in the conversation with concern disposition, detailed specifications, dependency map, current ready packet, gates, convergence, and a current launch register. Verify the baseline, authority, shared surfaces, independence rationale, and each ready step's explicit profile assessment. Refine an unstarted projection when material reality changed. Keep a started step's boundary stable unless an authorized correction changes it.

For a review or verification step, confirm that its specification identifies independently required evidence or a distinct unresolved concern beyond ordinary Slice evaluation.

Confirm internally that each ready Step can execute its required local evidence within the supplied route and authority. Add an isolated validation boundary to the assignment only when that authority is needed; otherwise omit routine readiness confirmation from the handoff or keep the Step gated when authority is missing.

## Start the ready packet

When the ready packet can create substantial local build, dependency, runtime, or validation state, confirm that available storage provides meaningful headroom for its concurrent routes. Keep the packet behind a storage gate rather than launching into plainly insufficient capacity.

Create each genuinely ready and independent Plan Step as a separate top-level task through the host harness. Apply both the model and reasoning level selected in its specification in the creation call, then compare the host-evidenced profile with the intended profile before delivering the assignment. A missing or mismatched field is a routing boundary rather than an implicit default.

Use the catalogue that supplied this operation as the instruction source: resolve its sibling `run-plan-step/SKILL.md`, verify that file is readable, and include its absolute path in the task prompt. Keep that instruction source separate from the repository or worktree change route. Host name resolution or a skill copy inside the child's worktree does not establish catalogue identity. Supply the fixed specification, repository or worktree route, relevant context, authority, boundaries, acceptance evidence, and this Plan Slice conversation's callback id.

Begin each task prompt with this routing header, populated with absolute paths and the actual callback id:

```text
AD-HOC TASK ROUTING
Role skill: <absolute run-plan-step/SKILL.md path>
Instruction catalogue: <absolute catalogue path>
Repository/worktree: <absolute task route>
Callback task: <Plan Slice task id>
```

Immediately after the header, tell the receiving conversation to read the exact role skill before acting, retain these routing values as distinct state, resolve operation skills only from that catalogue, and re-read the exact role skill after context compaction. These are prompt-carried routing facts; claim only the delivery evidence the host exposes.

Make each assignment self-contained. Supply authoritative artifact locations rather than directing the Plan Step to read the parent, a peer, or an earlier conversation. Use conversation ids only for ownership and callback routing.

Keep the assignment to task-specific content. State validation as an outcome boundary and the callback id as an address only. Invoke `run-plan-step` for investigation, validation method, checkpointing, reporting, callback action, waiting, tool use, and similar worker mechanics. Omit those instructions from the brief.

Pass a few neutral task clues rather than the parent's procedure or a dense rule set. Remove unaccepted solution candidates and command or check suggestions from the child brief. Refine an unstarted specification before launch when prescriptive wording does not protect a genuine hard boundary.

State task facts directly. Silently omit parent-only reasoning instead of explaining what was withheld, what the child may choose, or how it should perform or return its role.

Launch only a profile justified as the most appropriate fit for that step's ambiguity and context scope. A uniform or maximum profile without step-specific reasoning is not launch-ready.

Give concurrent mutable work routes where each step's changes can remain attributable; otherwise sequence the steps.

A collaboration subagent is not a Plan Step conversation. Launch each step once, record the evidenced task id and applied profile, and start all independent work in the packet. If the current instruction source, launch, profile application, or delivery is not evidenced, keep its status truthful.

Use one bounded confirmation check only when the creation result does not yet evidence the task route or activation; skip it when that evidence already exists. Once launch and delivery are evidenced, the operation is complete. Continue other slice work that can proceed now; otherwise state the pending callback in a short final response and end the turn. Do not wait for the callback within the same turn.
